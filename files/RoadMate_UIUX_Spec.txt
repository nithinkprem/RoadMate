1. Purpose & Conventions
This document catalogs every screen across RoadMate's three surfaces — Customer, Worker, and Admin/Super Admin — organized by the phase in which it ships. It is a specification of intent and content, not visual design; wireframes/high-fidelity mockups should be produced against this catalog as a separate design-file exercise (Figma), referencing the design tokens in the Frontend Design guidance used by the engineering team.
1.1 Design principles
Mobile-first: every screen is designed for a one-handed phone interaction first, since the dominant use case is a person standing next to a broken-down vehicle.
Two taps to help: from app open to seeing a nearby result should never exceed two taps/screens (location → issue → results).
Never a dead end: every screen has a visible path back or forward; error and empty states always suggest a next action (e.g. "No shops found — widen your search radius").
Trust signals up front: rating, open/closed, and verification badges are visible at the card level, not buried in a detail page.

5. Navigation Flow Summary
5.1 Customer primary flow (Phase 1)
Home (C1) → Issue selection (C2) → Results (C3) → Shop detail (C4) → [Call / Navigate / WhatsApp, exits to native app] or Write a review (C5, requires C6 login).
5.2 Customer primary flow (Phase 2+)
Shop/worker detail (C4) → Booking request (C8) → Searching (C9) → Worker assigned (C10) → Live tracking (C13, Phase 3) → Payment (C14, Phase 3) → Rate (C15, Phase 3). My Jobs (C11) is reachable from the main navigation at any time.
5.3 Worker primary flow
Registration (W1–W3) → Verification pending (W4) → Availability toggle (W6) → Incoming job request (W7) → Active job (W8) → Job history (W9).
5.4 Admin primary flow
Login (A1) → Listings (A2) [Phase 1] → Worker applications (A6) and Bookings board (A8) [Phase 2] → Ops analytics (A9) and Payments (A10) [Phase 3] → City configuration (A14) and Admin management (A15) [Phase 4].
